# karikosan

タスク・工程（ガントチャート）・車種別の進捗・予定をひとつにまとめた管理アプリです。iPhone・iPad・PC のブラウザで動き、ホーム画面に追加するとアプリ（PWA）として使えます。

公開 URL: https://sprintershota01172-collab.github.io/karikosan/

## できること

| 画面 | 主な機能 |
| --- | --- |
| ホーム | 「今日」と「4分割」を切り替え。4分割は優先度（至急・高・中・低）か、選んだ4つのグループで画面を4つに分け、各枠の＋でその枠に追加。今日: 今日のタスク（期限が今日・期限切れ・今日が期間内）を優先度（至急・高・中・低）ごとに区切って表示。完了、左スワイプで「延期」（次の作業日へ）・「除外」（今日だけ隠す、あとで戻せる）・「削除」。直近7日の予定。今日のタスクのクイック追加 |
| タスク | 車種 → グループ → 子ツリー → タスクの階層表示と、親への件数・進捗の集約。追加・編集・削除・完了（完了は「元に戻す」で取り消せる）。左スワイプで削除（大きくスワイプするとそのまま削除。「元に戻す」で戻せる）。長押しドラッグで並べ替え（同じグループの中。別のグループへは編集画面で移動）、並び順（手動・期限順・優先度別）。「優先度別」は 至急・高・中・低・完了 の見出しに分けて表示。優先度の印。グループは1つずつ開く（開くとほかを閉じて画面をコンパクトに）。絞り込み（状態・至急と高・担当者・キーワード）、グループへのジャンプ、グループの固定。チェックリスト（タスク画面内で切り替え） |
| ガント | 20行が画面に収まる表示。エクセルのような格子（日ごとの縦線・行ごとの横線・月の境目の濃い線）。左上に今見ている月。日・週・月の単位。タスク一覧と同じ並び・同じ開閉状態（優先度別も同じ）で、名前とバーは同じ行の中にあるためスクロールしてもずれない。グループの行のタップで開閉。バーのドラッグで期間の移動、両端で開始日・期限の変更（PC はマウス、スマホは長押ししてから。両端は選んだ行だけ）。横スワイプは日付が動くだけで、縦にずれたりバーが動いたりしない。土日は作業日にしない／する をタスクごとに設定。グループの期間・進捗の集約バー。行の長押しドラッグで並べ替え |
| 大日程 | 車種ごとのイベント（設計・試作・評価・生産準備・量産・その他）を1マス = 1週のガントで管理。「すべて」では車種ごとに重ならないイベントを同じ段に詰めた大日程と、週ごとの負荷（イベントの重み 小1・中2・大3 の合計）を色つきの数字で表示（ふつう 1〜3／多め 4〜6／とても多い 7以上）。車種を選ぶと、その車種のイベントを1件1行で表示し、負荷もその車種だけ。バーのドラッグで1週ずつ移動、両端で開始・終わりの週を変更（スマホは長押ししてから）。何もない所をタップでその週に追加。「年」にすると1年を見渡せる。月の区切りは週の単位（月をまたぐ週は月曜の月）。選んだバー（伸ばすモード）はほかの所をタップすると戻る |
| 予定 | 月カレンダー（左右スワイプで月を移動）、「今日」へ戻る、予定の追加・編集・削除、繰り返し（毎日・平日・毎週・毎月、終了日）、タスクの期限も表示 |
| 設定 | 文字の大きさ（10段階、全画面に反映）、完了の表示、並び順、グループを1つずつ開く、車種の管理（名前・色・順番）、書き出し・読み込み（JSON）、自動バックアップ（7日分）からの復元、サンプルデータ、アプリの版と更新の確認 |

そのほか: 全体検索（タスク・予定・大日程・グループ・車種）、操作の取り消し（50回まで）、オフラインでの起動・操作。

### 画面のつくり

- グループは1つずつ開いて画面をコンパクトに保ちます（設定の「グループは1つずつ開く」でオフにできます）。一覧は指で縦にスクロールできます
- 文字を打つとき: 「＋ 追加」を押すと入力欄が画面の上に出ます。入力画面（シート）もスマホでは上まで広げ、入力欄を上側に置きます。入力欄がキーボードより上にあるので、iPhone が画面をずらしません。それでもずれたときは、アプリとシートを見えている範囲に合わせます
- 見た目: 丸みのある文字（iPhone・Mac は丸ゴシック、Windows は Meiryo UI）、白いカードとやわらかい影、丸いボタン

### 優先度の自動判断

優先度を「自動」（初期値）にしたタスクは、次の式で判断します。編集画面に理由が出ます。手動で 至急・高・中・低 を選ぶと、そちらが優先されます。

余裕（作業日）＝ 今日から期限までの作業日 − 残りの作業（予定の作業日 ×（1 − 進捗））

| 優先度 | 条件 |
| --- | --- |
| 至急 | 期限を過ぎた・今日が期限・日数が足りない（余裕がマイナス） |
| 高 | 余裕が3日以内 |
| 中 | 余裕が10日以内 |
| 低 | それより先・期限なし |

土日作業なしのタスクは土日を作業日に数えません（祝日は作業日として数えます）。

## 使い方（iPhone）

1. Safari で公開 URL を開く
2. 共有ボタン →「ホーム画面に追加」
3. 新しい版を公開すると、アプリを開いたときに「新しい版があります → 更新する」が出ます

データはその端末のブラウザの中（IndexedDB）に保存されます。別の端末へは 設定 →「書き出す」「読み込む」で移せます。

## 開発

```sh
npm install
npm run build        # dist/ に出力（GitHub Pages の /karikosan/ でも、ほかのパスでも動くように相対パス）
npm run typecheck    # 型チェック
npm test             # データ・日付・並べ替えのテスト（node:test）
npm run test:e2e     # 画面のテスト（Playwright。先に build が必要）
npm run check        # 上のすべて
npm run icons        # public/icon.svg を変えたときだけ: PNG アイコンを作り直す（sharp が必要）
```

`main` に push すると GitHub Actions（`.github/workflows/pages.yml`）が 型チェック → テスト → ビルド → 画面のテスト を行い、すべて通ったときだけ GitHub Pages に公開します。初回だけ、リポジトリの Settings → Pages → Source を「GitHub Actions」にしてください。

### 構成

```
src/
  model/      データの型・日付計算（作業日）・優先度・大日程（週ごとの負荷・段の詰め方）・スキーマとマイグレーション・行の組み立て・操作（純粋関数）・繰り返し・検索
  store/      状態（小さな atom ストア）・保存（IndexedDB、localStorage への控え）・取り消し
  ui/
    screens/  ホーム・タスク・チェックリスト・ガント・大日程・予定・設定
    gantt/    ガントの描画とバーのドラッグ
    drag/     長押しドラッグの並べ替え
    components/ 共通の部品（行・シート・スワイプ・チェック・トグルなど）
scripts/build.mjs  ビルド（esbuild）・manifest・Service Worker・version.json の生成
tests/        ロジックのテスト
e2e/          画面のテスト（5つの画面サイズ・タッチ操作・重点シナリオ）
```

### 設計で気をつけたこと

- **ガントと一覧のずれをなくす**: ガントは1つの表示領域で、各行が「名前（横方向に固定）」と「バー」を持ちます。名前とバーが別々にスクロールしないので、構造上ずれません。行は一覧と同じ関数（`buildRows`）で作ります。
- **ドラッグで振動させない**: ドラッグ開始時に行の位置を一度だけ測り、指の位置との比較で挿入先を決めます。ほかの行は transform で動かすだけで、確定（指を離したとき）までデータも DOM の順番も変えません。ドラッグの transform と画面切り替え・並び替えのアニメーション（FLIP）は別の要素・別の段階で動かし、重ならないようにしています。
- **データを失わない**: 変更は120ms後に IndexedDB へ保存し、アプリを閉じる・裏に回すときは即座に保存したうえで localStorage にも控えを書きます。起動時は新しい方を使います。読み込んだデータはスキーマを確認して修復・移行（`migrate`）し、壊れたものは取り込みません。1日1回の自動バックアップを7日分残します。
- **更新が反映されない問題を防ぐ**: Service Worker のキャッシュ名に版の番号（ソースの中身から作るハッシュ）を入れ、HTML は常にネットワーク優先、`version.json` は常にネットワークから取ります。新しい版を見つけたら案内を出し、「更新する」で切り替えます。
- **文字の大きさ**: すべて rem で指定しているので、`html` の文字サイズ1か所を変えるだけで全画面に反映されます。大きくしたときは、ボタンの文字や担当者表示を隠して重なりを防ぎます。

### 推奨構成との違い

指示書の推奨構成（Vite・Tailwind・Zustand・dnd-kit・Motion・Vitest）は使っていません。開発環境から npm のパッケージを取得できなかったため、手元にあった React・TypeScript・esbuild・Playwright で作り、次のものは自前で実装しました。

| 推奨 | 実際 | 理由・中身 |
| --- | --- | --- |
| Vite | esbuild（`scripts/build.mjs`） | Vite の中身も esbuild。ファイル名へのハッシュ付け・manifest・Service Worker の生成を含む |
| Zustand | `src/store/store.ts` | `useSyncExternalStore` を使う同等の小さな仕組み（セレクターで必要な部分だけ再描画） |
| dnd-kit | `src/ui/drag/sortable.ts` | 長押し・スクロールとの区別・自動スクロール・transform だけで動かす並べ替え |
| Motion | CSS アニメーションと FLIP | 画面切り替え・並び替え・シート |
| Vitest | node:test（tsx） | テストの書き方はほぼ同じ |
| Tailwind / CSS Modules | 1つの CSS（`src/ui/styles.css`） | デザインの値は CSS 変数にまとめている |

## 共同編集（未実装）

いまはデータをその端末の中だけに保存しています。複数の端末・メンバーでの同期は**実装していません**（設定画面にも「未設定」と表示しています）。

GitHub Pages は静的なファイルを配るだけなので、認証・リアルタイム同期・通知には外部のバックエンド（Supabase など）が必要です。接続するときは次の方針で作れるよう、データを用意しています。

- すべての項目（車種・グループ・タスク・予定・チェックリスト）が一意の `id` を持ち、タスクと予定は `updatedAt` を持つ
- データの変更はすべて `src/model/actions.ts` の純粋関数を通る（同期の送信はここ1か所につなげられる）
- 同期の単位は項目ごと。競合は項目ごとの `updatedAt` で新しい方を採用し、削除は削除の印（tombstone）を残して伝える
- 認証はバックエンドのログイン（Supabase Auth など）を使い、ワークスペースごとの権限はバックエンド側の行レベルのセキュリティで管理する。公開してよい接続先の URL と公開用のキー以外の秘密の情報は、フロントエンドにも GitHub にも置かない
- 共同編集を設定しなくても、いまの機能はすべて使える

## 制約

- 祝日は考慮していません（作業日は土日だけで判定）
- テストは Playwright の Chromium で、iPhone・iPad の画面サイズとタッチ操作を再現して行っています。iPhone の実機（Safari）での確認はしていません
